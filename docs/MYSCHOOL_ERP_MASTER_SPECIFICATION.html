Product Overview & Strategic Problem

MYSchool PRD — Core Vision & Guardrails
🎯 The Downside of Not Having This System
  • Delayed Duty-of-Care Alerts: Manual 8:30 AM paper registers delay time-sensitive absence alerts to parents.
  • Accounting Ledger Drift: Unverified digital fee receipts and bounced transfers cause ledger discrepancies.
  • Lost Statutory Records: Uncoordinated departures risk the permanent loss of regulatory exit certificates.
  • Morning Roll-Call Crashes: Unpooled serverless queries crash under 100+ concurrent classroom spikes.
🏁 What Success Looks Like
  • Digitizes, automates, and connects all daily academic and administrative operations across JSS School.
  • 100+ classroom teachers log 40 students simultaneously in under 60 seconds with single-payload writes (~10ms).
  • Fee dues deduct only after campus bursar verifies physical bank statement reconciliation.
  • Mandatory verified exit certificates (TC, Character, No-Dues) strictly guard permanent student deletions.
  • Students retain lifetime access to download official historical transcripts and report cards.

Core Functional Modules & Workflows

Seven Non-Negotiable Operational Pillars
⚡ High-Speed Attendance Roll-Call
Teachers load class rosters in one click. Single-action submit dispatches one array payload (createMany) committing 40 records in ~10ms. Real-time webhook fires SMS/push alerts for unexcused absences.
💳 Manual Fee UTR Verification
Shows fee dues and UPI intents. Validates UTR uniqueness against duplicates and supports partial payments. Balance is strictly untouched until campus bursars audit physical bank statements.
📝 Student Leave Applications
Parents submit leave requests with date spans and doctor attachments, routed to Class Teachers. Approved leaves automatically flag calendar roll-calls as locked EXCUSED_LEAVE.
👨‍👧‍👦 Multi-Ward Single Parent Hub
Dedicated single-parent family model (no dual-parenting complexity). One login manages multiple wards across campuses with persistent top navbar switching.
🔒 Exit-Certificate Deletion Barrier
Permanent student deletions require typed admission_no confirmation and are hard-blocked until 4 statutory certificates (TC, Character, Migration, No-Dues) are verified.
📄 Background Batch PDF Engine
Buzzer Token pattern hands back a jobId in ~30ms. Inngest renders 2,000 admit cards and term receipts directly to Supabase Storage with 24-hour pre-signed download links.
📅 Academic Cycles, Historical Grade Archives & Faculty Substitution
JSS School defines annual academic cycles. Past attendance archives to cold storage while students retain permanent lifetime access to download official transcripts. HODs assign daily period substitutes with automated timetable collision checks; staff attendance is tracked with daily timestamps.

System Architecture & Concurrency Strategy

Engineering Stability for 5,000+ Users
[ Client Web / Mobile ] │ ▾ [ Cloudflare Edge CDN & Security Shield ] (DDoS / WAF / SSL) │ ▾ [ Full-Stack Next.js Application Engine ] (React 19 + Server Actions) │ ┌────&boxbot;─────────────────────────────┐ ▾ ▾ [ Supabase Supavisor ] [ Inngest Queue Worker ] (Port 6543 - Transaction Pool) (Async Batch PDF Generation) │ │ ▾ ▾ [ Supabase PostgreSQL 16+ ] [ Supabase Private Storage ] (Multi-Branch Relational DB) (Exit Docs, Admit Card Bundles)
1. Supavisor Pooling
Solves serverless socket exhaustion. 500 concurrent teacher requests multiplex across 15–25 physical database connections via transaction pooling on port 6543.
2. Direct Pre-Signed Uploads
Large student admission PDFs and exit certificates upload directly from client browsers to Supabase Storage, bypassing Next.js server memory and bandwidth.
3. Asynchronous PDF Jobs
Inngest handles mass admit cards and fee receipts off-thread. Administrators receive an active progress bar and a 24-hour signed download URL upon job completion.
Failure Scenario Root Cause & Real-World Risk Technical Handling Strategy & Safeguard
8:30 AM Attendance Surge Serverless Socket Exhaustion: 100+ teachers submitting simultaneously spins up hundreds of serverless threads, depleting PostgreSQL's 100-connection limit and crashing with 500 Internal Error. Bulk Payload + Supavisor Pooling: Single array payload of 40 students committed in ~10ms via Prisma createMany. Supavisor (Port 6543) transaction mode holds sockets only during active write, multiplexing 500+ callers into 15–25 physical connections.
Batch PDF Generation HTTP 504 Gateway Timeout: Compiling 500+ admit cards with student photos and barcodes takes 1–3 minutes, exceeding the 60s reverse proxy / browser timeout limit. Inngest Async Token Pattern: Offloaded to Inngest with instant 200 response and jobId in ~30ms. Headless worker renders in chunks, streams PDFs to Supabase Storage, and issues a 24h pre-signed download link.
Invalid Fee UTR Number Ledger Drift & Fraud: Naive systems deduct student fee dues immediately on submission. If bank transfer fails or UTR is fake, accounting ledgers desynchronize. Two-Step Manual Audit Queue: Submissions are tagged PENDING_VERIFICATION; due balance remains untouched until campus bursar audits bank records and clicks [VERIFY & APPROVE].
Unverified Student Deletion Regulatory Liability & Lost Transcripts: Deleting a student before statutory clearance violates education board mandates and destroys academic history. Statutory Exit Barrier Guard: Hard programmatic check in deletion API. Verifies that Transfer Certificate (TC), Character Certificate, and No-Dues Slip exist with status VERIFIED before deletion.

Operational Laws for Autonomous Vibe Coding
1. Inspect →
Examine existing schema & folder boundaries
2. Plan →
Identify affected types & verify non-destructive rules
3. Implement →
Write minimal, isolated code in feature directory
4. Verify ✓
Run compiler check (tsc --noEmit)
✓ DO Working Rules
  • ✓ Scope all queries by branchId AND departmentId.
  • ✓ Use single-array createMany inserts for morning roll-calls.
  • ✓ Import database singleton from @/lib/db (Supavisor pool).
  • ✓ Require verified exit certificates before student deletion actions.
  • ✓ Separate domain logic into features/*/server/*.service.ts.
✖ AVOID Strict Prohibitions
  • ✖ Never execute prisma db push --force-reset or drop columns.
  • ✖ Never execute unconstrained school-wide database lookups.
  • ✖ Never instantiate new PrismaClient() inside feature files.
  • ✖ Never deduct fee balances automatically without staff verification.
  • ✖ Never generate batch PDFs on the main Next.js HTTP thread.
⚙️ Core Engineering & Code Hygiene Directives
  • Feature-Sliced Architecture: Organize code strictly under src/features/[feature]/ (components, service, schemas).
  • Dumb UI, Smart Services: UI components only handle render/local state; all business logic lives in *.service.ts.
  • Uniform API Envelopes: Enforce { success, data, error, metadata } across all Route Handlers and Server Actions.
  • Universal Error Handling: Use custom error classes (AppError, UnauthorizedError) with safe try/catch envelopes.
  • Strict Naming Standards: PascalCase for components, camelCase for functions/hooks, snake_case for PostgreSQL entities.
  • Zod Environment Validation: Validate all runtime variables at boot via @/config/env.ts; never read process.env directly.
  • Proactive Dead-Code Removal: Eliminate unused imports, dead functions, and obsolete code during every feature cycle.
