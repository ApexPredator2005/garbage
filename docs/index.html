Product Requirements Document

A clear plan before the first line of code.
01 Product overview High-level details about the product, platform, audience, and goal.
Product
MYSchool ERP — High-concurrency educational network platform.
Platform
Responsive Full-Stack Web (Next.js 19 App Router, Tailwind CSS, shadcn/ui).
Audience
JSS School (Central Trust, Principals, Wing Coordinators, Teachers, Bursars, Parents).
Goal
Digitize, automate, and connect all daily academic and administrative operations, absorb 8:30 AM attendance spikes, and enforce strict manual UTR fee audits.
02 Problem & goal The operational risks of not having an integrated system versus unified success.
🎯 The problem we solve (Downside of not having this system)
  • Delayed Duty-of-Care Alerts: Manual 8:30 AM paper registers delay critical absence notifications to parents.
  • Accounting Ledger Drift: Unverified fee receipts and bounced transfers cause severe financial discrepancies.
  • Lost Statutory Records: Uncoordinated student departures risk permanent loss of regulatory exit certificates.
  • Morning Roll-Call Crashes: Unpooled database connections crash under concurrent classroom attendance spikes.
🏁 What success looks like
  • Digitizes, automates, and connects all daily academic and administrative operations across JSS School.
  • 100+ classroom teachers log 40 students simultaneously in under 60 seconds with single-payload writes (~10ms).
  • Fee dues deduct only after campus bursar verifies physical bank statement reconciliation.
  • Mandatory verified exit certificates (TC, Character, No-Dues) strictly guard permanent student deletions.
  • Students retain lifetime access to download official historical transcripts and report cards.

Architecture & Data

Define how every part connects, pools, and commits.
01 System overview A modular, full-stack application with clear boundaries.
💻 Client Layer
Next.js 19 React Server Components (RSC) and Client components. Scoped by dynamic route segments (/[branch]/[dept]/[module]) with direct-to-S3 pre-signed upload streams.
⚙️ Application Layer
Unified Next.js Server Actions with strict Zod validation schemas. Business rules isolated inside @/features/* domain services. Inngest headless task queue for async jobs.
🗄️ Data Layer
Supabase PostgreSQL 16+ accessed via Supavisor pooler (Port 6543) in Transaction Mode. Direct Port 5432 reserved for migrations. Private S3 buckets for certificates.
02 Technology stack Modern, reliable tools chosen for developer experience and long-term scalability.
Layer Technology Architectural Role
Frontend & API Next.js 15+ (React 19) Unified App Router eliminates cross-origin CORS errors and shares Zod contracts.
Database Supabase PostgreSQL 16+ Managed relational engine with 7-day Point-In-Time Recovery (PITR).
Connection Pooler Supavisor (Port 6543) Transaction pooling holds connections only during query run (~10ms), multiplexing 500+ users.
Authentication NextAuth.js (Auth.js v5) Credentials Provider with HTTP-only, encrypted JWT cookies; validates roles in Edge middleware with 0ms DB latency.
Background Queue Inngest Renders mass PDFs off-thread, returning instant job IDs to prevent 504 timeouts.
Document Engine @react-pdf/renderer Compiles watermarked admit cards and grade transcripts directly to private S3.

05 Dependency rules Keep the system modular and easy to maintain.
1. UI uses Services
UI components only handle form inputs and visual state. All database reads and writes route strictly through @/features/*/server/*.service.ts.
2. Services Enforce Rules
Business logic lives in services. Never deduct balances without staff UTR approval; never delete students without verified exit certificates.
3. Additive Migrations
Never drop or rename existing database columns. All schema evolution must be additive (new nullable fields or new tables) using Port 5432.
06 Failure handling Plan for failures, prevent crashes, and maintain audit integrity.
Scenario Failure Risk & Root Cause Technical Handling Strategy & Safeguard
8:30 AM Attendance Surge Serverless Socket Exhaustion: 100+ teachers submitting simultaneously spins up hundreds of serverless threads, depleting PostgreSQL's default 100-connection limit and crashing the DB with 500 Internal Error. Bulk Payload + Supavisor Pooling: UI submits 1 single array with 40 students committed in ~10ms via Prisma createMany (100 total queries vs 4,000). Supavisor (Port 6543) transaction mode holds sockets only during query execution, multiplexing 500+ teachers into 15–25 physical connections.
Batch PDF Generation HTTP 504 Gateway Timeout: Compiling 500+ admit cards with photos, barcodes, and watermarks takes 1–3 minutes of heavy CPU time, exceeding the 60s reverse proxy / browser timeout limit. Inngest Async Token Pattern: Next.js offloads the batch job to Inngest and returns an instant 200 response with jobId in ~30ms. Headless worker renders cards in chunks, streams PDFs to Supabase Storage, and issues a 24-hour pre-signed download link to the admin dashboard.
Invalid / Unmatched Fee UTR Ledger Drift & Fraudulent Clearance: Automatically deducting student fee dues immediately upon parent submission risks severe accounting desynchronization if the bank transfer bounces or the UTR is invalid. Two-Step Manual Audit Queue: Submissions are tagged PENDING_VERIFICATION; student balance remains strictly untouched. Campus bursar checks physical bank records; only manual [VERIFY & APPROVE] decrements dues and generates an immutable digital receipt.
Unverified Student Deletion Regulatory Liability & Lost Transcripts: Deleting or archiving a pupil before issuing statutory board documents creates severe educational compliance violations and irreversible record loss. Statutory Exit Barrier Guard: Hard programmatic check in the deletion API. Verifies that Transfer Certificate (TC), Character Certificate, and No-Dues Slip exist with status VERIFIED in student_documents before allowing deletion confirmation.
